# StudyBuddy backend (MVP)

A minimal FastAPI backend: upload lecture notes/slides, extract the text,
flag files that came through too sparse/garbled to trust, then generate
study questions that are grounded in the uploaded material (every question
carries a source excerpt, and ungrounded ones are dropped automatically).

## 1. One-time setup

From inside this folder:

```bash
# Create an isolated Python environment so this project's packages
# don't clash with anything else on your machine.
python3 -m venv venv

# Activate it (you'll need to do this every time you open a new terminal
# to work on the project).
source venv/bin/activate        # Windows: venv\Scripts\activate

# Install all the packages this project needs.
pip install -r requirements.txt
```

## 2. Add your API key

```bash
cp .env.example .env
```

Then open `.env` and paste in a real Anthropic API key (get one at
https://console.anthropic.com/ -> Settings -> API Keys). Never commit this
file -- add `.env` to a `.gitignore` before you push to GitHub.

## 3. Run it

```bash
uvicorn app.main:app --reload
```

Leave that running, then open **http://127.0.0.1:8000/docs** in your browser.
That page is auto-generated by FastAPI and lets you try every endpoint --
upload a file, generate questions, etc. -- without writing any frontend
code yet. This is the fastest way to check the backend works before you
start wiring up the UI.

A file `studybuddy.db` will appear in this folder the first time you run
it -- that's your whole database, nothing else to install.

## How it fits together

```
POST /documents/upload
    -> extracts text from the file (pdf/docx/pptx/txt)
    -> runs a confidence check (flags thin/garbled material)
    -> saves a Document row, returns its id + confidence info

POST /documents/{id}/questions/generate
    -> sends the document's text to Claude with strict grounding rules
    -> keeps only questions that come with a real source excerpt
    -> saves Question rows, returns them

GET /documents/{id}/questions
    -> fetches previously generated questions for that document
```

## What's deliberately left out of this MVP

- **User accounts / login** -- every document is global for now. Add this
  only if your course requirements need multiple distinct users.
- **File storage** -- extracted text is saved in the database; the original
  uploaded file itself is not kept.
- **Database migrations** -- tables are just created fresh on startup. Fine
  for a 4-week solo project; don't over-engineer this.
- **Rate limiting / retries on the Claude API call** -- add basic error
  handling around `generate_questions` if you see it fail in testing.

## Next steps (suggested order)

1. Run the server, upload a real set of notes via `/docs`, and sanity-check
   the extracted text and confidence result.
2. Generate questions for that document and read through them -- check the
   source excerpts actually match the material.
3. Once the backend behaves the way you want, start the frontend and point
   it at `http://127.0.0.1:8000` (CORS is already open for local dev).
4. Come back and tighten things up (error messages, edge cases) once the
   UI is calling the real endpoints and you can see where it breaks.
